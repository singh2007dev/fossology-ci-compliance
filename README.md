# fossology-ci-compliance
CI pipeline integration for automated software license compliance using FOSSology

A beginner-friendly Python tool to automate open-source license compliance in continuous integration (CI) pipelines using scan reports generated by [FOSSology](https://www.fossology.org/).

---

## 🎯 Overview

Software projects commonly incorporate open-source dependencies and third-party files. Ensuring that every file conforms to an approved open-source license policy is critical before shipping software.

This tool acts as a bridge between **FOSSology** and **GitHub Actions**:
1. Reads scan results from FOSSology's JSON report format.
2. Extracts detected licenses and human audit conclusions per file.
3. Evaluates licenses against a transparent, configurable compliance policy.
4. Distinguishes compliant licenses (e.g., MIT, Apache-2.0) from policy violations (e.g., AGPL-3.0) and unapproved findings requiring review.
5. Emits a clean report summary with an explicit **`BUILD STATUS: PASS`** (exit code `0`) or **`BUILD STATUS: FAIL`** (exit code `1`) to enforce compliance in CI.

---

## 📋 Verified FOSSology Report Format

In official FOSSology REST API implementations (specifically the `GET /uploads/{id}/licenses` endpoint), scan findings are provided in the following JSON structure:

```json
[
  {
    "filePath": "src/main.py",
    "findings": {
      "scanner": ["MIT"],
      "conclusion": ["MIT"]
    }
  },
  {
    "filePath": "src/helpers/utils.py",
    "findings": {
      "scanner": ["Apache-2.0"],
      "conclusion": null
    }
  },
  {
    "filePath": "docs/readme.txt",
    "findings": {
      "scanner": ["No_license_found"],
      "conclusion": null
    }
  }
]
```

### Key Fields:
- **`filePath`**: Relative path of the scanned file.
- **`findings`**: Object containing license findings:
  - **`scanner`**: Array of license identifiers discovered by automated scanners (such as Nomos, Monk, or Ojo). When no license is detected, FOSSology reports `["No_license_found"]` or an empty list.
  - **`conclusion`**: Array of human-cleared/reviewed licenses (or `null` if not cleared). When present, human conclusions take precedence over raw scanner findings.

## ⚙️ Configurable Compliance Policy

Compliance policies are defined in a simple JSON file (see `compliance_policy.json`):

```json
{
  "allowed_licenses": [
    "MIT",
    "Apache-2.0",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
    "Unlicense",
    "CC0-1.0"
  ],
  "denied_licenses": [
    "AGPL-3.0-only",
    "AGPL-3.0-or-later",
    "GPL-2.0-only",
    "GPL-2.0-or-later",
    "GPL-3.0-only",
    "GPL-3.0-or-later",
    "SSPL-1.0"
  ],
  "allow_unlicensed": false
}
```

### Evaluation Logic:
- **`PASS`**: Every detected license is present in `allowed_licenses`.
- **`DENIED` (Violation)**: Any detected license matches `denied_licenses`. Triggers `BUILD STATUS: FAIL`.
- **`NEEDS_REVIEW` (Review Required)**:
  - A file has an unapproved license not listed in `allowed_licenses` or `denied_licenses`.
  - A file has no detected license (`No_license_found`) and `allow_unlicensed` is `false`.
  - Triggers `BUILD STATUS: FAIL` until reviewed and cleared.

## 🚀 How to Run

### Requirements
- Python 3.8+ (Uses only Python standard library; no `pip install` required!)

### 1. Run the Compliance Checker
Check a report using the default policy:
```bash
python3 compliance_checker.py --report samples/sample_report_pass.json
```

Check a report with a custom policy:
```bash
python3 compliance_checker.py --report samples/sample_report_pass.json --policy compliance_policy.json
```

### 2. Observe Output and Exit Codes

#### Passing Example:
```bash
python3 compliance_checker.py --report samples/sample_report_pass.json
```
```
============================================================
       FOSSology CI License Compliance Summary
============================================================
Total Files Scanned : 3
Passed Files        : 3
Denied Files        : 0
Review Required     : 0
Detected Licenses   : Apache-2.0, BSD-3-Clause, MIT
------------------------------------------------------------
============================================================
BUILD STATUS: PASS
============================================================
```
*(Exit code: `0`)*

#### Failing Example (Prohibited Licenses):
```bash
python3 compliance_checker.py --report samples/sample_report_fail.json
```
```

       FOSSology CI License Compliance Summary

  - src/vendor/network_module.py

    Reason: Prohibited license(s) detected: GPL-3.0-only

============================================================
BUILD STATUS: FAIL
============================================================
```
*(Exit code: `1`)*

## 📊 CSV Report Usage

In addition to JSON reports, the compliance checker supports tabular CSV scan reports (such as those generated from FOSSology UI exports or SPDX-aligned clearing spreadsheets).

> [!NOTE]
> CSV support uses recognized column headers to parse tabular scan data. CSV is **not** an official FOSSology REST API endpoint response format (which returns JSON via `/api/v1/uploads/{id}/licenses`), but is commonly exported from FOSSology web UI actions and SPDX export workflows.

### Recognized Column Headers
The CSV reader identifies columns case-insensitively:
- **File path columns**: `filePath`, `FileName`, `file_path`
- **Detected license columns**: `scanner`, `LicenseInfoInFile`, `license`, `licenses`
- **Concluded license columns** *(optional)*: `conclusion`, `LicenseConcluded`, `concluded`

Multiple licenses within a single cell may be separated by commas (`,`) or semicolons (`;`). Placeholder values such as `NONE` or `NOASSERTION` are recognized as missing license indicators (`No_license_found`).

### Running with a CSV Report

#### Passing Example:
```bash
python3 compliance_checker.py --report samples/sample_report_pass.csv
```
*(Evaluates compliant licenses and exits with code `0` / `PASS`)*

#### Failing Example:
```bash
python3 compliance_checker.py --report samples/sample_report_fail.csv
```
*(Detects prohibited copyleft licenses and exits with code `1` / `FAIL`)*

## 🤖 GitHub Actions CI Integration

To automate compliance checks on every push or pull request, see `.github/workflows/compliance.yml`.

Example CI step:
```yaml
- name: Check License Compliance
  run: |
    python3 compliance_checker.py --report path/to/fossology_report.json --policy compliance_policy.json
```

If any file contains a prohibited license or an unapproved license requiring review, `compliance_checker.py` exits with status `1`, causing the CI pipeline build to fail immediately.

## 💡 Assumptions and Limitations

1. **Input Format**: Assumes JSON output compatible with the official FOSSology REST API (`GET /uploads/{id}/licenses`), containing a list of objects with `filePath` and `findings` (`scanner` list and optional `conclusion` list).
2. **First Implementation Scope**: Focuses strictly on report evaluation and CI build pass/fail gating. In accordance with requirements, it does not include direct REST API network polling, databases, user notifications, or dashboard UIs.
3. **Clearing Precedence**: Concluded licenses (`conclusion`) represent verified human compliance clearing decisions and take precedence over automated scanner detections.
